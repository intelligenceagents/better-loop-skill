## Repairs and independent functional checks

- Older host reports are now historical context after a new delta; current reports must match the active local assessment.
- Replayed outcomes, copied check bytes, edited notes and changed verdict labels cannot create later-check chronology.
- Material action or acceptance-check changes get a new recommendation association; they cannot inherit completed progress.
- SKILL trigger requirements no longer apply to ordinary AGENTS/CLAUDE instruction files. Omitted recommendation sources have explicit visibility/source mappings.
- Distant edits use separate bounded line-matching hunks. A complexity fallback is explicitly labeled samples, not removed/added lines. Real diff regressions retain the initial failure.
- Collection no longer invokes `git status`: an actual configured-clean-filter test demonstrated it could execute a filter. Fixed index/HEAD reads and the collector's own comparisons avoid that behavior.
- Omitted callees/tests remain unverified, not missing. Attestations remain reported claims; matching selected-human-message evidence is required for observed human actions in both directions.

Five journey findings and two evidence findings passed independent bounded retests. These checks are scoped functional reviews, not a general security certification or independently calibrated coaching evaluation.

## Interpretation

The observed workflow supports choosing scope, retaining local reports, cross-host recall, assessing changed evidence and avoiding duplicate progress. It does not guarantee host brevity or factual accuracy, assess arbitrary full session histories, validate all task families, prove improvement, identify the best hire, or provide a general human ranking. The final native repair checks were Claude sessions; final-source Codex model interpretation was not rerun.

The harness explicitly requested remembered context, an improvement opportunity and an acceptance check even on return. That prompt pressure limits interpretation of the brevity failure.
