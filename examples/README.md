# Synthetic examples

Every example is invented and labeled `content_origin: synthetic`. None represents a real user, actual benchmark run, proven improvement, or publishable cleared payload.

| File | Purpose |
|---|---|
| [Software story](software-story.synthetic.json) | Favorable normalized resource metric with a quality floor |
| [Analysis story](analysis-story.synthetic.json) | Lower resource use with a quality failure; a mixed result |
| [Research story](research-story.synthetic.json) | A useful next experiment with no measured improvement |
| [Local evaluation](evaluation-run.synthetic.json) | Five fictional paired trials, complete records and missing metrics |

The first KPI is the prespecified primary metric when making a structured improvement claim. Public indices are rounded to five points; actual work-derived values stay local. A rounded equality cannot substantiate a public numerical improvement. Local evidence references are forbidden in public candidates.

These fixtures pass draft structural contracts only. A later production builder must minimize and scan actual candidates, reconcile narrative claims, and obtain exact-payload approval. Synthetic demonstrations must remain excluded from live benchmark counts, progress awards, rankings and candidate matching.
